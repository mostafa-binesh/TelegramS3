# Contributing

## Expectations

- Work from evidence, not assumptions.
- Keep changes scoped.
- Update docs when behavior changes.
- Preserve unrelated worktree changes.

## Workflow

1. Inspect the relevant upstream or local code.
2. Make the smallest correct change.
3. Run the targeted tests and formatting checks.
4. Update the docs and ADRs if the design changed.

## Commit Style

- Use Conventional Commits.
- Keep subjects short and in English.

## Review Notes

- Call out unsupported or partially supported behavior explicitly.
- Do not soften security or recovery guarantees to make tests pass.
